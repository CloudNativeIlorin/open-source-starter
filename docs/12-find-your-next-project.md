# Find Your Next Project 🌍

You've made your first contribution.

Now what?

The best way to keep learning open source is to **keep contributing**.

You don't need to jump into a huge project immediately.

Start with something that interests you.

---

## Start with your interests

Think about things you already enjoy or want to learn.

For example:

### If you like coding

You could contribute to:

* Web applications
* Mobile applications
* Developer tools
* APIs
* Cloud projects
* DevOps tools
* Open-source libraries

### If you like writing

You could help with:

* Documentation
* Tutorials
* Blog posts
* Guides
* README files
* Technical explanations

### If you like design

You could contribute to:

* UI/UX
* Design systems
* Graphics
* Illustrations
* Accessibility
* Website improvements

### If you like finding problems

You could help with:

* Testing
* Bug reports
* Quality assurance
* Reproducing issues
* Security research

### If you like working with people

You could contribute through:

* Community support
* Events
* Project management
* User support
* Community moderation
* Mentoring

### If you speak multiple languages

You could help with:

* Translation
* Localization
* Language review
* Documentation translation

There are many ways to contribute.

# Where can you find projects?

There are thousands of open-source projects on GitHub.

You can search GitHub for topics you're interested in.

For example:

```text
cloud native
kubernetes
python
javascript
cybersecurity
documentation
design
education
```

You can also look for issues labelled:

```text
good first issue
beginner
documentation
help wanted
first contribution
```

These labels can help you find issues that may be suitable for new contributors.

Keep in mind that labels are set by individual projects, so their meaning and quality can vary.

---

# Don't choose a project just because it's popular

A project doesn't have to be famous for you to learn from it.

A smaller project may actually give you more opportunities to:

* Ask questions
* Meet maintainers
* Understand the codebase
* Make contributions
* Get feedback

Look for projects that interest you and have an active, welcoming community.

---

# Read the project's contribution guidelines

Before contributing to a new project, look for files such as:

```text
README.md
CONTRIBUTING.md
CODE_OF_CONDUCT.md
```

Also check the project's GitHub pages for contribution instructions.

Read them before opening an issue or Pull Request.

Different projects have different rules.

For example, a project might require:

* A specific branch naming style
* Certain commit message formats
* Tests before submitting a PR
* A particular Pull Request template
* Specific tools or versions
* Discussion before starting certain features

Following the project's guidelines makes contributing easier for everyone.

---

# Look at existing Pull Requests

This is one of the best ways to learn how a project works.

Before making your own contribution, look through some existing Pull Requests.

Pay attention to:

* How contributors describe their changes
* How maintainers review contributions
* How feedback is handled
* What kinds of changes are accepted
* How contributors respond to questions

You can learn a lot just by watching how other people collaborate.

---

# Start small

You don't have to fix a huge problem on your first day.

Try something manageable.

For example:

```text
Fix a typo
    ↓
Improve documentation
    ↓
Fix a small bug
    ↓
Add a test
    ↓
Improve an example
    ↓
Build a small feature
```

Your skills will grow as you contribute.

---

# It's okay to learn while contributing

You don't need to know everything before making your first contribution.

In fact, open source can be a great place to learn.

You might start thinking:

> "I don't know how this works."

Then:

> "Let me read the documentation."

Then:

> "Let me ask a question."

Then:

> "I think I understand it now."

That's learning.

---

# Find your contribution path

Instead of asking:

> "Am I a developer?"

Try asking:

> **"What can I contribute?"**

Maybe you can:

```text
Build        → code, testing, cloud, DevOps
Design       → UI/UX, graphics, accessibility
Write        → docs, tutorials, guides
Test         → QA, bug reports, reproduction
Translate    → localization, language support
Research     → analysis, data, investigation
Organize     → projects, events, community
Communicate  → support, education, community
```

And if you don't see your skill here, that's okay.

Open source projects need people with different backgrounds and abilities.

---

# Keep a record of your contributions

As you contribute to different projects, keep track of your work.

You can use your GitHub profile to show:

* Projects you've contributed to
* Pull Requests you've opened
* Issues you've reported
* Documentation you've written
* Projects you've helped maintain

Over time, this becomes a record of what you've learned and built.
