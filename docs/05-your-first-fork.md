# Your First Fork 🍴

You've learned what open source is.

You've learned who can contribute.

You've learned the basics of Git and GitHub.

Now it's time to do something.

We're going to create your own copy of this project.

This is called **forking** a repository.

---

# What Is a Fork?

A fork is your own copy of someone else's repository on GitHub.

For example, this project belongs to Cloud Native Ilorin.

You can create your own copy of it under your GitHub account.

```text
Cloud Native Ilorin
       │
       │  Fork
       ▼
Your GitHub account
       │
       ▼
Your own copy of the project
```

You can make changes to your copy without directly changing the original project.

Later, you can ask Cloud Native Ilorin to review your changes through a Pull Request.

---

# 🛑 Before You Start

Make sure you have:

* A GitHub account
* A web browser
* A stable internet connection

You **do not need Git installed yet** to complete this step.

We'll install and use Git when we clone the project.

---

# Step 1 — Open the Repository

Go to the CNI Open Source Starter repository.

If you are reading this guide from the repository, you are already there.

At the top of the page, you'll see information about the project.

You should see a button labelled:

**Fork**

Click it.

---

# Step 2 — Choose Where to Fork

GitHub will ask where you want to create the fork.

Select your GitHub account.

GitHub will then create a copy of the repository under your account.

For example:

```text
Cloud Native Ilorin
open-source-starter
```

becomes something like:

```text
YourUsername
open-source-starter
```

The exact username will depend on your GitHub account.

---

# Step 3 — Check Your Fork

After GitHub finishes creating the fork, you should be taken to your new repository.

Look near the top of the page.

You should see your GitHub username associated with the repository.

You may also see information showing that the repository was forked from Cloud Native Ilorin's repository.

That's how you know you're working on your own copy.

But you've completed an important part of the open-source workflow.

```text

       │
       │
       ▼
```

# 🤔 Why Don't We Just Edit the Original Repository?

Good question.

In many open-source projects, you won't have permission to directly change the original repository.

Instead, you make your own copy.

This gives you a safe place to work.

You can experiment, make changes and prepare your contribution without directly changing the project's main code or documentation.

---

# 🧠 Fork vs Clone

You'll soon hear another word:

**Clone**

Fork and clone are not the same thing.

### Fork

A fork creates your own copy of a repository **on GitHub**.

```text
GitHub
   │
   ├── Original repository
   │
   └── Your fork
```

### Clone

A clone downloads a repository **from GitHub to your computer**.

```text
GitHub
   │
   │ clone
   ▼
Your computer
```

So the usual process looks like:

```text
Fork
 ↓
Clone
 ↓
Make changes
 ↓
Commit
 ↓
Push
 ↓
Pull Request
```

We'll learn each step.

---

# ⚠️ A Common Beginner Mistake

Make sure you're working on **your fork**, not the original repository.

Before making changes, check the repository owner shown on GitHub.

You should see your own GitHub username.

If you're unsure, stop and check before continuing.
