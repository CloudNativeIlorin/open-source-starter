# What Is Open Source? 🌍

If you've never heard of open source before, don't worry.

Let's start from the beginning.

## So, what does "open source" mean?

Open source simply means that the source code or other materials behind a project are made available under a license that allows people to use, study, modify, and share them according to that license.

But open source is about more than just code.

It is also about people working together to build, improve, share and maintain projects.

Think of it like a community kitchen.

Someone provides the kitchen and the recipe.
Someone else improves the recipe.
Another person notices something that doesn't work.
Someone else writes better instructions.
Another person helps new people learn how to use it.

Everyone can contribute something useful.

That's the idea behind open source.

---

## 💻 Is Open Source Only About Coding?

**No.**

This is one of the biggest things we want you to understand.

When people hear "open source", they often think:

> "I'm not a programmer, so I can't contribute."

That's not true.

Open-source projects need different kinds of people.

For example:

### Developers 👨🏾‍💻

Developers can:

* Build new features
* Fix bugs
* Improve existing code
* Review code
* Improve performance

### UI/UX Designers 🎨

Designers can:

* Improve interfaces
* Create designs
* Improve user experience
* Create design systems
* Review existing designs

### Writers ✍🏾

Writers can:

* Write documentation
* Improve tutorials
* Fix unclear explanations
* Create guides
* Improve project websites

### Cybersecurity Professionals 🔐

Security professionals can:

* Identify security issues
* Improve security documentation
* Review security practices
* Help projects understand vulnerabilities

### Product Managers 📦

Product people can:

* Understand user needs
* Help define features
* Organize priorities
* Improve product documentation
* Help projects focus on useful problems

### Testers 🧪

Testers can:

* Find bugs
* Test new features
* Reproduce problems
* Improve testing processes

### Translators 🌍

Translators can:

* Translate documentation
* Make projects accessible to more people
* Help communities communicate across languages

### Community Builders 🤝

Community contributors can:

* Welcome new contributors
* Answer questions
* Organize events
* Create community resources
* Help people get involved

And there are many more ways to contribute.

You could be a student, researcher, Arabist, designer, developer, writer, cybersecurity professional, product manager, community builder, or simply someone who wants to help.

**Your skill doesn't have to be technical for it to be valuable.**

---

# Why Do People Contribute to Open Source?

People contribute for different reasons.

Some people want to:

* Learn new skills
* Build experience
* Work with other people
* Improve a project they use
* Solve problems
* Build their portfolio
* Meet people in the community
* Give back to projects they benefit from
* Help other people
* Explore a new area of technology

There isn't one correct reason to contribute.

If you find something you care about and you can help improve it, that's a good place to start.

---

# What Does a Contribution Look Like?

A contribution doesn't have to be huge.

Imagine you find a project with a documentation page that says:

> "Run the following command to install the application."

But the command is wrong.

You could report the problem.

Or you could fix the documentation and submit the change.

That's a contribution.

You could also:

* Fix a spelling mistake
* Improve an explanation
* Add an example
* Translate a page
* Report a bug
* Test a feature
* Improve a design
* Write a tutorial
* Answer a question
* Fix code
* Build a new feature

Sometimes the smallest contribution can save someone else hours of frustration.

---

# 🌱 Your First Contribution Doesn't Have to Be Perfect

One thing you'll learn throughout this journey is that you don't need to know everything before you start.

You will make mistakes.

You might open a Pull Request and get feedback.

You might not understand a Git command.

You might ask a question that someone else has asked before.

That's okay.

**That's how learning works.**

The goal isn't to become an expert before making your first contribution.

The goal is to learn by participating.
