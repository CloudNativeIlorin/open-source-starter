# Contributing to CNI Open Source Starter

Welcome! 👋

We're glad you're here.

This project is built to help people understand open source and make their first contribution without feeling lost.

You don't have to be an experienced developer to contribute. You can help with documentation, design, testing, research, translations, community support, code, or even something as simple as fixing a typo.

## Before you contribute

If you're completely new to open source, start with:

* [What is Open Source?](docs/01-what-is-open-source.md)
* [Who Can Contribute?](docs/02-who-can-contribute.md)
* [What is GitHub?](docs/03-what-is-github.md)

You should also take a look at our [Code of Conduct](CODE_OF_CONDUCT.md).

## Your first contribution

If this is your first time contributing to GitHub, don't worry.

We've created a step-by-step guide that walks you through the whole process:

1. Fork the repository
2. Clone your fork
3. Create a branch
4. Make a small change
5. Commit your change
6. Push your branch
7. Open a Pull Request
8. Get feedback
9. Make changes if needed
10. Get your contribution merged 🎉

You can follow the full guide starting here:

[Your First Fork](docs/05-your-first-fork.md)

## A simple place to start

For your first contribution, you can add your name to `CONTRIBUTORS.md`.

Example:

```text
- Your Name — [@your-github-username](https://github.com/your-github-username)
```

That's it.

It may seem small, but you'll go through the same basic workflow used when contributing to larger open source projects.

## What can you contribute?

Here are some examples:

* Fix a typo
* Improve documentation
* Add an example
* Test something
* Report a bug
* Improve the design
* Translate content
* Research a topic
* Write code
* Help other contributors
* Suggest an improvement
* Organize or support the community

If you can make something better, there's a good chance you can contribute.

## Creating a branch

Please create a separate branch for your contribution instead of working directly on `main`.

For example:

```bash
git switch -c add-my-name
```

Try to give your branch a name that describes what you're working on.

Examples:

```text
fix-typo
improve-readme
add-example
update-documentation
add-my-name
```

## Commits

Keep your commits clear and simple.

For example:

```bash
git commit -m "Add my name to contributors"
```

Your commit message should give a quick idea of what changed.

## Pull Requests

When you're ready, open a Pull Request from your branch to the project's `main` branch.

In your Pull Request:

* Explain what you changed.
* Keep the description simple.
* Mention anything you think the reviewer should know.
* If you're fixing an issue, link to it when appropriate.

Don't worry if your Pull Request isn't perfect.

Pull Requests are also part of the learning process.

## Reviews and feedback

Someone may review your contribution and ask you to make changes.

That's normal.

You can make the changes on the same branch and push them again. Your existing Pull Request will update automatically.

If something isn't clear, ask questions.

The goal isn't to get everything right on the first try. The goal is to learn and improve.

## Stuck?

If you get stuck, you're not doing anything wrong.

Open an issue, ask a question, or reach out through the Cloud Native Ilorin community.

Someone else has probably been confused by the same thing before.

## Most importantly

Don't wait until you feel like an expert.

Start small.

Ask questions.

Learn as you go.

Help someone else when you can.

**Learn. Build. Contribute.**
